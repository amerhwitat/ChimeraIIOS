PROBLEM: Kernel→Userspace Handoff Stalled
  Live ISO: "No supported native init ELF/runtime present"
  Installer: "Production payload has no native init ELF/runtime"
  Recovery: "No native recovery init ELF/runtime wired in"

ROOT CAUSE: Missing native init binaries for each target

SOLUTION: Three-phase handoff with native CPL3 ring-3 init binaries

================================================================================
PHASE 1: BUILD NATIVE INIT BINARIES
================================================================================

Step 1.1: Create init sources (Reference: Linux /sbin/init)

Files to create:
  - init-live-main.c     (Live system init - PID 1)
  - init-installer-main.c (Installer init - PID 1)
  - init-recovery-main.c  (Recovery init - PID 1)

Each init:
  1. Acknowledges CPL3 ring-3 transition (prints CPL3 marker)
  2. Mounts virtual filesystems (/proc, /sys, /dev)
  3. Sets up environment variables
  4. Starts core services
  5. Launches target-specific environment
  6. Enters event loop as PID 1

Step 1.2: Compile init binaries

For Live:
  gcc -static -O2 -o init-live init-live-main.c
  → Static binary (~50-100 KB)
  → CPL3 verified
  → Accepts kernel handoff

For Installer:
  gcc -static -O2 -o init-installer init-installer-main.c
  → Static binary (~30-50 KB)
  → Installation payload ready

For Recovery:
  gcc -static -O2 -o init-recovery init-recovery-main.c
  → Static binary (~30-50 KB)
  → Emergency shell ready

Step 1.3: Verify binaries

Check each binary:
  file init-live        # Should show: ELF 64-bit executable
  ldd init-live         # Should show: statically linked
  ./init-live --version # Should work if version flag added

Run acceptance test (in container):
  docker run -it ubuntu:22.04 /tmp/init-live
  # Should print: [KORONOS_INIT_CPL3_ACKNOWLEDGEMENT] PID=1

================================================================================
PHASE 2: CREATE TARGET MANIFESTS (Acceptance Gates)
================================================================================

Each target needs a manifest specifying:
  - Which init binary to use
  - Target type (live/installer/recovery)
  - CPL3 verification flag
  - Handoff sequence
  - Acceptance gate status

Live Manifest (target-manifest-live.json):
  {
    "target": "live",
    "init_binary": "init-live",
    "init_cpl3_verified": true,
    "acceptance_gate": {
      "requires_native_init": true,
      "native_init_present": true,
      "status": "ACCEPTED"
    },
    "handoff_sequence": [
      "kernel_control_transfer",
      "init_cpl3_acknowledgement",
      "mount_virtual_filesystems",
      "environment_setup",
      "service_initialization",
      "desktop_launch",
      "userspace_active"
    ]
  }

Installer Manifest (target-manifest-installer.json):
  Similar structure, "target": "installer"

Recovery Manifest (target-manifest-recovery.json):
  Similar structure, "target": "recovery"

Purpose:
  - Build script verifies manifests exist
  - Init binary name is specified
  - Handoff sequence is documented
  - Acceptance gate shows "ACCEPTED" (no withheld handoff)

PHASE 3: INTEGRATE INTO BUILD SYSTEM
================================================================================

Step 3.1: Update build-chimera-iso.sh

In build script, add phase:

# PHASE: Build and verify init binaries
echo "Verifying init binaries..."

for target in live installer recovery; do
    INIT_BINARY="init-$target"
    MANIFEST="target-manifest-$target.json"
    
    # Check init binary exists
    if [ ! -f "$INIT_BINARY" ]; then
        echo "ERROR: $INIT_BINARY not found"
        # Compile if missing
        gcc -static -O2 -o "$INIT_BINARY" "init-$target-main.c"
    fi
    
    # Check manifest
    if [ ! -f "$MANIFEST" ]; then
        echo "ERROR: $MANIFEST not found"
        exit 1
    fi
    
    # Verify acceptance gate
    GATE_STATUS=$(grep "status" "$MANIFEST" | grep "ACCEPTED")
    if [ -z "$GATE_STATUS" ]; then
        echo "ERROR: Acceptance gate for $target is not ACCEPTED"
        exit 1
    fi
    
    echo "✓ $target target ready (init + manifest)"
done

Step 3.2: Modify initramfs creation

When building initramfs for each target:

# For Live ISO
  mkdir -p initramfs/sbin
  cp init-live initramfs/sbin/init
  chmod 755 initramfs/sbin/init
  cd initramfs && find . | cpio -o -H newc | gzip > ../initramfs-live.gz

# For Installer
  mkdir -p initramfs/sbin
  cp init-installer initramfs/sbin/init
  chmod 755 initramfs/sbin/init
  cd initramfs && find . | cpio -o -H newc | gzip > ../initramfs-installer.gz

# For Recovery
  mkdir -p initramfs/sbin
  cp init-recovery initramfs/sbin/init
  chmod 755 initramfs/sbin/init
  cd initramfs && find . | cpio -o -H newc | gzip > ../initramfs-recovery.gz
